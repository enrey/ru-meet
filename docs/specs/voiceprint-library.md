# Локальная библиотека голосов участников

Статус — первая версия реализована (`frontend/src-tauri/src/audio/voiceprint.rs`, страница «Голоса»). Пороги сопоставления предварительные: замерены на четырёх встречах (`voiceprint_report`), требуют калибровки на записях с известными и новыми участниками.

## Цель

Пользователь один раз запоминает голос коллеги из записи встречи. После диаризации следующей встречи ru-meet предлагает имя знакомого участника. Пользователь подтверждает предложение одним нажатием, и имя появляется в транскрипте и экспорте.

Функция работает после диаризации, в том числе при штатном распознавании речи через GigaAM v3. Для неё достаточно сохранённого аудио и интервалов говорящих. Временные метки отдельных слов не требуются.

## Сценарий пользователя

1. В панели участников завершённой встречи пользователь выбирает «Спикер 2» → «Запомнить голос…».
2. Приложение предлагает прослушать несколько фрагментов, где слышен только этот участник. Пользователь может исключить ошибочно размеченный фрагмент, ввести имя «Анна Смирнова» или выбрать существующий профиль. Если пригодных фрагментов мало, приложение объясняет причину и предлагает выбрать другую запись.
3. После диаризации новой встречи рядом с анонимной меткой появляется предложение «Похоже, Анна Смирнова» с действиями «Подтвердить» и «Отклонить». Перед выбором можно прослушать реплику.
4. После подтверждения реплики в этой встрече и экспорт получают имя Анны. Хороший фрагмент можно отдельно добавить к её профилю, например если на новой записи она говорит через другую гарнитуру. Отклонение сохраняет прежнюю подпись.
5. В настройках пользователь может посмотреть список профилей, переименовать профиль, удалить отдельный образец или забыть голос целиком. Удаление профиля прекращает будущие сопоставления и сохраняет уже подтверждённые подписи в истории встреч.

## Получение и сопоставление отпечатков

- Использовать один экстрактор голосовых признаков WeSpeaker с фиксированной версией модели и предобработки. Он получает звук по интервалам диаризации. Благодаря этому сохранённый профиль можно использовать при переключении между Polyvoice, Speakrs и Sortformer.
- Брать несколько достаточно длинных интервалов с одним активным голосом. Исключать наложения и сборную метку `Others`. Учитывать достаточность чистой речи и согласованность образцов. Короткого «да» недостаточно для регистрации человека.
- Хранить нормализованные векторы отдельных подтверждённых образцов. Для профиля рассчитывать усреднённый нормализованный вектор. Сравнивать кандидатов по косинусному сходству в пределах одной версии экстрактора.
- Предлагать имя, когда несколько реплик согласуются, лучший кандидат проходит порог сходства и достаточно опережает второго. Для единственного профиля в библиотеке по-прежнему необходим абсолютный порог. При слабом или неоднозначном совпадении оставлять анонимную метку.
- Подобрать пороги на разных встречах с известными и новыми участниками. Основной показатель — доля правильных предложений имени. Дополнительно измерять долю узнанных знакомых участников и частоту ошибочных предложений для новых голосов.

## Хранение и интеграция

Использовать локальную SQLite. Для профиля хранить постоянный ID и отображаемое имя, для образца — ID профиля, вектор, версию экстрактора и ссылку на исходную встречу и интервал. Для прослушивания использовать существующую запись без дублирования аудио. При удалении образца пересчитывать представление профиля.

Связь между спикером конкретной встречи и профилем хранить отдельно от строки имени. Различать предложение и подтверждённое назначение. Только подтверждённое имя попадает в экспорт. Два одноимённых человека могут иметь разные профили. Действие «Переименовать» внутри встречи сохраняет свой текущий смысл, а добавление образца в библиотеку требует явного выбора «Запомнить голос».

Повторная диаризация может перенумеровать спикеров. Сохранять ручные подписи и переносить подтверждённые связи только при однозначном сопоставлении по исходным интервалам. Совпадения номера «Спикер 2» между запусками недостаточно. Повторная обработка одной записи не должна создавать дубликаты образцов.

## Критерии приёмки первой версии

1. Пользователь может создать профиль из старой встречи с сохранёнными аудио и диаризацией, в том числе если в транскрипте нет таймингов слов.
2. Контрольный сценарий включает две разные встречи. В первой пользователь сохраняет Анну и Игоря. Во второй Анна говорит через другую гарнитуру и участвует новый коллега. На проверенной записи приложение предлагает Анну и оставляет нового участника без имени. Фиксируются также результаты на других доступных записях.
3. До подтверждения в экспорте остаётся прежняя подпись. После подтверждения имя совпадает в панели спикеров, транскрипте и экспорте. Отклонение предложения не добавляет образец в профиль.
4. При наложении голосов, недостатке речи или двух близких кандидатах приложение воздерживается от предложения. Обычная расшифровка и ручное именование по-прежнему доступны.
5. Проверены повторная диаризация, совпадающие отображаемые имена, смена движка диаризации и удаление профиля. Чужие реплики не получают имя из-за совпадения номера спикера или имени профиля.
